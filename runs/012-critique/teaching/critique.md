## Findings

### 1. Objectives (score 6)

- **Slide 1–2** — The five learning objectives in `talk-context.md` are never stated to the audience as objectives; the deck opens with the thesis ("context, not intelligence") but not with "you will leave able to X." An attendee can't check afterward whether they got what they came for. **Fix:** add one clause to slide 1's spoken subtitle or slide 2's body, e.g. "leave able to: pick a pattern, write one subagent, read a run's logs." **Cost:** slide 2 is already the tightest slide (47-word ceiling, 47 used). Pay for it by cutting the already-flagged phrase "inspectable, not a claim that it beats a person" (the script itself marks this as the first thing to cut if behind pace) — reuse that same 6 words of headroom for the objectives line instead of losing it entirely. Severity: **must-fix**.

- **Slide 12 / handout §"Agents in .claude/agents/"** — Objective 2 ("write a subagent as a markdown file and call it from a script, headless, with a budget cap") is only ever shown as a screenshot of *this repo's* `critic.md`; the literal frontmatter skeleton and the literal headless invocation syntax (the command + budget flag an attendee would type) never appear as text anywhere in slides or handout. Watching a screenshot of someone else's file is recognition, not the recipe. **Fix:** add the actual command line used by `run_agent` in `pipeline/run.sh` (with its budget flag) as literal text on slide 12 or in the handout. **Cost:** slide 12 is spoken at ~71 words against a 140-word ceiling — 69 words of headroom, no cut needed elsewhere. Severity: **must-fix**.

### 2. Generalization (score 5)

- **Slides 6–9 (all four pattern slides)** — Each pattern slide gives the shape and the evidence but not the transferable recipe demanded by the rubric: what file to write, what command to run, what to check. What's shown is always this repo's instance (astronomy asides are hypothetical, not files). An attendee leaves able to *recognize* fan-out, pipeline, writer-critic, and worktrees, not to *build* one from a blank repo. **Fix:** replace the handout's current per-agent prose list (8 lines, one bullet per agent describing what it does) with one generic 3-line template — frontmatter skeleton, one invocation command, one check to run on the return — followed by the existing bullets as a single worked example. **Cost:** handout-only change, no slide/time budget impact; trim the "Five links" section from five numbered citations to three (keep Anthropic subagents, worktrees, and Kim et al.; the other two are already on the Sources slides) to hold the handout to one page. Severity: **must-fix**.

### 3. First step (score 4)

- **Slide 26 / handout** — Nowhere does the deck or handout say the one concrete first action for someone's own project ("write one subagent .md file for your most annoying bounded subtask, invoke it once headless, check the return is under ~2,000 tokens") or its prerequisites (Claude Code CLI access, a repo with a `CLAUDE.md`, permission to run headless/non-interactively). The closing slide restates the thesis, not a next action. **Fix:** add one sentence to slide 26's scripted opening line, before the floor opens: "First thing to try Monday: pull one bounded, read-only subtask out of your normal Claude Code session into its own agent file, run it once, and check the summary length." **Cost:** slide 26's scripted portion is only ~17 words against a 180-second segment that is "mostly open floor" (168 s unscripted) — this fits with room to spare; no cut needed. Severity: **must-fix**.

### 4. Mental model (score 7)

- **Slides 6–9** — "Pick by task shape, not by ambition" (slide 5) and the reconciling data (slide 10) state the second half of the decision rule crisply, but none of the four pattern slides restates which shape it answers in matching words, so an attendee skimming only the pattern slides must infer the shape-to-pattern mapping rather than read it. **Fix:** add a 3–4 word shape tag to each pattern slide's title, e.g. "Pattern 1 · Fan-out and merge — shape: independent," "Pattern 2 · Pipeline — shape: sequential." **Cost:** ~3 words per slide, 12 words total; slides 6–9 run 161–204 words against a 210-word ceiling each, so all four absorb this with headroom and no time added. Severity: **nice-to-have**.

### 5. Failure literacy (score 6)

- **Slide 16 vs. slide 26 speaker notes** — `talk-context.md` requires three build failures to be "shown, not hidden": spec contradiction, worktree merge conflict, budget exhaustion. Only the merge conflict gets a slide (16); the spec contradiction (run 002) and budget exhaustion (run 006) exist solely in the speaker's private Q&A reference notes for slide 26, surfaced only if an attendee happens to ask "did the pipeline get anything wrong?" If that question isn't asked, two of the three required failures — and any habit for catching them — are never communicated. **Fix:** add one line each to slide 16's body, next to the merge-conflict line that's already there: e.g. "Also caught: a spec contradiction (two time budgets) before writing began; a budget cap that stopped a revision mid-way." **Cost:** slide 16 is spoken at ~110 words against a 210-word ceiling for its 90-second slot — 100 words of headroom absorbs this; if more room is needed, cut slide 25 ("How it actually fails") to the one-sentence version the script already designates as "CUT #1 CANDIDATE," freeing the full 40 s / ~73 words elsewhere. Severity: **must-fix**.

- **Slide 14** — The duplicate-citation failure (two researchers cited the same source under different URLs) is narrated as an interesting fact ("independent agents disagree on details") but never converted into a stated habit (e.g., "the merge step deduplicates citations by URL, not by title"). **Fix:** add the six-word fix clause to slide 14's body or note. **Cost:** slide 14 runs at ~135 words against a 210-word ceiling — 75 words of headroom. Severity: **nice-to-have**.

### 6. Cognitive load (score 7)

This is denser than the one-new-idea-per-slide target, even though it stays under the 40-word body cap. **Fix:** move the Osmani verification-bottleneck line to slide 23 ("Isolate the files, centralize the merge"), where "who checks the merge" is already the topic, and keep slide 9 to the worktree mechanism plus the Cognition caveat. **Cost:** removing ~12 words from slide 9's body; slide 23 is at ~163 words against its own 163-word ceiling exactly, so trim the Kim et al. clause there from "independent agents with no central check amplified errors 17.2x; with centralized verification, 4.4x" to "no check: 17.2x error amplification; centralized check: 4.4x" (saves ~8 words) to make room. Severity: **nice-to-have**.

- **Slide 8 speaker note → slide 25** — The term "MAST" is used in slide 8's note ("In MAST, the failure taxonomy on slide 25...") before it is ever defined; MAST is named only in slide 25's *speaker note*, never in any slide's visible body text at all. A speaker or reader going slide-by-slide hits an undefined acronym out of order. **Fix:** add "(MAST)" to slide 25's visible body text, which currently just reads "1,600+ traces, 7 frameworks, 14 failure modes [Cemri 2025]," and soften slide 8's forward reference to "we'll see the full taxonomy shortly" instead of naming MAST early. **Cost:** one word added to slide 25's body (currently ~73 words against a 93-word ceiling — ample room); zero time cost. Severity: **nice-to-have**.

### 7. Take-home (score 5)

- **Sources slide 4 speaker note** — reads: "the repo URL goes here once it is public." Every artifact the handout tells the audience to go read afterward — `runs/NNN-<stage>/`, `.claude/agents/*.md`, `pipeline/run.sh`, `runs/cost-report.md` — is a path inside this repo. If the repo is not public and the URL is not filled in by talk day, an attendee has no way to reach any of it, and the entire take-home promise of the handout collapses to zero, regardless of how good its prose is. **Fix:** publish the repo (or at minimum the `runs/`, `.claude/agents/`, `pipeline/`, `handout/` directories) before 11:15 Day 2 and fill in the URL on Sources slide 4; if that's not possible in time, inline the actual agent frontmatter and the actual `pipeline/run.sh` command syntax as literal text in the handout so it stands alone without repo access. **Cost:** no slide/time budget impact (handout and Sources-slide text only); if inlining frontmatter, shorten the handout's "Five links" list from five to three entries to hold it to one page. Severity: **must-fix**.

- **Handout §"Where the logs and cost report live"** — states, in the document the audience takes home, that `runs/cost-report.md` "only reflects stages through 003-outline" and that `runs/cost.tsv` "currently has an unresolved git merge-conflict marker... sitting in it... which will need fixing before the report can be rebuilt correctly." An attendee who follows the handout's own instructions to `pipeline/run.sh cost` right after the talk will hit this exact broken state, and the handout doesn't say whether it will be fixed before the talk (a bug to remove) or is being deliberately preserved to match the merge-conflict story on slide 16 (a lesson to keep, but then it should say so). **Fix:** either resolve the conflict and regenerate a complete cost report before the talk, or add one clause to the handout — "left unresolved on purpose, matching the merge conflict on slide 16 — resolve it yourself with `pipeline/run.sh cost --rebuild` before trusting the totals" — so the audience isn't confused about whether they're looking at a bug or a demonstration. **Cost:** one sentence added to the handout; no slide/time impact. Severity: **must-fix**.
